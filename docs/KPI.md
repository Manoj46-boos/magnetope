# The KPI contract

Generated by `npm run docs` from the funnel reader’s own steps, the Friday report’s own sections and the benchmark constants the report judges against. The suite re-renders this file and compares it byte for byte, so a step, a section or a benchmark that drifts from the readers fails the build (R-AN-05).

Every KPI names where it is read from, the segment it splits by, the benchmark it answers and the one decision it arms — a number that arms no decision is deleted, not admired (Kaushik). Each milestone runs on one metric that matters (Croll), declared below.

## The session-0 funnel (R-AN-06)

Seven steps, one per row, in the order a first visit either climbs or falls off. The drop between adjacent steps is the playtest fix list — the funnel says which step lost them, never why:

| Step | The record that marks it |
| --- | --- |
| boot | the boot record itself, labelled fresh |
| first-input | the `input` record, with its boot-to-touch seconds |
| first-clear | an `attempt` record that ends clear |
| level-3-entry | a `level` enter on the campaign’s third level |
| first-par | a `time` record at or under that level’s own par |
| first-ghost | the `ghost` record, the run going on record |
| first-cosmetic | the first `cosmetic` unlock, from any path |

## The KPI table

| KPI | Read from | Segment | Benchmark | The decision it arms |
| --- | --- | --- | --- | --- |
| Conversion to play | the funnel’s first-input share | locale × device | 75% overall, 70% on touch, against Poki’s 65% healthy floor | the boot and the opener: re-read the first four seconds, then the thumbnail |
| Time to first touch | the input record’s own seconds | device | the load law’s ceilings: 3 s desktop, 6 s touch | where the boot spends its milliseconds — the cold-load budget |
| First-clear conversion | the funnel’s first-clear share | locale × device | the on-ramp’s own promise: the first two levels are guaranteed-clearable | the on-ramp: catch window, assist, telegraphs |
| Average playtime | the visit length the session records report | locale × device | 7 min against Poki’s 5 min floor | pacing: the review queue, the dangle cadence, the celebration stack |
| Fall rate per level | the difficulty report | level | the level’s own target and band | retune the level, or re-lay it |
| Ghost adoption | the funnel’s first-par and first-ghost shares | session-0 | no invented floor — it arms the par-honesty audit, not a quota | the par ghosts’ pacing (the author’s own time plus twenty) |
| Dangle conversion | the dangle reader | look | no invented floor — a look shown and never taken reprices | the shelf’s prices and the card’s rotation pool |
| Sink health | the pacing reader’s spend-of-earned ratio | visit | the sim’s own over-accumulation law, 2% | prices, or a new sink |
| Perf tier reach | the tier census | device | the mid tier holds the frame budget on the reference machine | the tier thresholds — the watchdog’s are W13’s to build |

## The Friday report (R-AN-07)

One command, `npm run friday -- export.jsonl`, regenerates the five sections the weekly retune ritual reads (R-LD-16, R-RT-10), every one of them split by the boot record’s own locale and device (R-AN-09):

1. difficulty
2. session-0 funnel
3. economy pacing
4. dangle
5. perf tiers

## The one metric per milestone (Croll)

| Milestone | The one metric that matters |

| M3 — The Game | First-clear conversion, the on-ramp’s own gate |

| M5 — The Submission | The playtime median — the slowest-moving third of the web-fit trio |

## The laws

- **SDK-only** — every record rides the SdkBus’s measure channel; the page opens no other (R-AN-02).
- **Child-safe vocabulary** — no PII, no free text, no fingerprinting beyond the SDK’s own surface; every payload enumerated (R-AN-03).
- **Absence changes nothing** — with the channel blocked or gone, the game plays and saves identically (R-AN-08).
- **Every number splits by segment** — locale × device, read off the boot record, so a desktop/mobile gap can never hide in a median (R-AN-09).
